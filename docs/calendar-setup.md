# Підключення Google Calendar: що зробити в Google Cloud

Інструкція для власника. Робиться один раз, руками, у браузері. Код на сайті
без цих кроків просто мовчить — жодна сторінка не ламається.

Порядок важливий: **спершу опублікувати екран згоди, потім підключати людей.**
Інакше доведеться підключати всіх удруге за тиждень (див. крок 4).

---

## 1. Окремий OAuth-клієнт

Консоль: <https://console.cloud.google.com/apis/credentials> — той самий
проєкт, де вже живе ключ Google Maps.

1. **Enable APIs** → знайти «Google Calendar API» → **Enable**.
2. **Credentials** → **Create credentials** → **OAuth client ID** →
   тип **Web application**.
3. Назва: `Budvik Calendar`.
4. **Authorized redirect URIs** — додати обидва рядки, знак у знак:

   ```
   https://www.budvik27.com/api/calendar/google/callback
   http://localhost:3000/api/calendar/google/callback
   ```

5. Зберегти. Google покаже **Client ID** і **Client secret** — вони
   знадобляться в кроці 5.

> Клієнт саме окремий, а не той, яким люди входять на сайт. Той — вхід
> покупця на вітрину, і додавати туди календарний дозвіл означало б питати
> згоду на календар у кожного роздрібного клієнта.

---

## 2. Дозвіл (scope)

**APIs & Services** → **OAuth consent screen** → **Data access** →
**Add or remove scopes**. Знайти й додати рівно один календарний рядок:

```
https://www.googleapis.com/auth/calendar.app.created
```

Разом із ним Google сам додасть базові `openid` та `email` — вони потрібні,
щоб у кабінеті було видно, який саме акаунт підключено.

**Тут варто подивитися уважно.** Навпроти рядка консоль пише, до якої
категорії він належить:

- позначки **Sensitive** немає → верифікація застосунку **не потрібна**,
  крок 4 зводиться до однієї кнопки;
- стоїть **Sensitive** → потрібна верифікація, див. крок 4.

Це єдине місце, де видно точну відповідь, і вона може змінитися з часом —
тому дивимось у консолі, а не покладаємось на пам'ять.

> `calendar.app.created` дає доступ **лише до календарів, які створив сам
> застосунок**. Особистих подій сайт не бачить і зіпсувати їх не може — прав
> немає.

## 4. Опублікувати (найважливіший крок)

**OAuth consent screen** → **Publishing status** → **Publish app**.

Поки статус — **Testing**, Google видає постійний ключ доступу **на 7 днів**.
Тобто конектор працюватиме тиждень, а потім у всіх разом попросить
підключитися знову. Публікація це знімає.

- Якщо в кроці 2 позначки **Sensitive** не було — на цьому все.
- Якщо була — Google попросить подати застосунок на перевірку: підтвердити
  домен у Search Console, показати політику конфіденційності на тому ж домені
  й записати коротке відео, де видно, як людина натискає «Підключити» й дає
  згоду. Розгляд зазвичай 3–5 робочих днів.

**Чекати розгляду не обов'язково**, щоб почати користуватися: опублікований,
але ще не перевірений застосунок працює. Люди бачитимуть екран
«Google hasn't verified this app» → **Advanced** → **Go to Budvik**. Для
десятка співробітників це прийнятно; верифікація прибирає це попередження.

## 5. Ключі на сервері

Три змінні. Одна з них — новий ключ шифрування; згенерувати його можна так:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

| Змінна | Значення |
|---|---|
| `CALENDAR_TOKEN_KEY` | рядок із команди вище |
| `GOOGLE_CALENDAR_CLIENT_ID` | Client ID з кроку 1 |
| `GOOGLE_CALENDAR_CLIENT_SECRET` | Client secret з кроку 1 |

Класти **в обидва місця**:

- сайт — Vercel → Settings → Environment Variables (Production);
- воркер — Railway → сервіс `budvik-sync-worker` → Variables.

`CALENDAR_TOKEN_KEY` має бути **однаковий** на сайті й на воркері: сайт ним
шифрує ключ доступу при підключенні, воркер — розшифровує при синхронізації.

> Втратити цей ключ не страшно: постійний ключ доступу Google — це дозвіл,
> який можна видати заново, а не дані. Люди просто підключаться ще раз.

---

## 6. Перевірка

Після викочення коду й накату міграції:

```bash
npx tsx --env-file=.env scripts/calendar-sync-dry.mts
```

- До налаштувань: «Конектор вимкнено — немає …». Це нормальна відповідь.
- Після: «Підключень немає» — значить, ключі на місці й конектор чекає людей.

Далі — профіль на сайті → картка «Google Календар» → **Підключити**. За
хвилину-дві в Google з'явиться календар «Budvik», а в ньому — ваші задачі зі
строком.

Якщо календаря не видно в телефоні: застосунок Google Календар → меню →
«Налаштування» → увімкнути «Budvik». Нові календарі там інколи вимкнені за
замовчуванням.
