# Розвідка «бухгалтерії» на сервері 1С

Чотири скрипти, усі **тільки читають**. Перші два виконано 05.09.2026 (виводи
`~/Downloads/probe-server-bases.out.txt`, `probe-accounting-in-ut.out.txt`),
підсумок знахідок — у пам'яті `1c-accounting-recon`. Головне: у кластері є
друга база **`Buhgalteria`**; в УТ банку немає взагалі, зате є 24 організації,
кредиторка постачальникам −17,5 млн, партії на 18 млн собівартості (31%
старші за 2024) і 335 статей витрат, які заповнює не РКО.

## Що ми знаємо без запуску

Обмін читає з бази `kavetskiy` (УТ для України 2.3) торговий шар: каталог,
ціни, залишки, замовлення, реалізації, повернення, надходження, собівартість
продажів, ПКО, дебіторку. Це все, що є в `queries.json`.

Гроші в цій базі — **лише каса**: `ПлатежноеПоручениеВходящее` існує, але за
рік 0 проведених; `ПоступлениеНаРасчетныйСчет`, `БанковскаяВыписка` відсутні
(проба `probe-bank-payments.ps1`, 10.08.2026). Водночас:

- договори клієнтів звуться «Безготівка» / «Поставка факт» — тобто частина
  клієнтів платить на рахунок, і ці гроші десь обліковуються;
- на сервері стоїть M.E.Doc — податкова звітність зазвичай живиться з
  бухгалтерської бази, не з УТ;
- 286 надходжень за два роки в USD — імпорт, за який хтось платить валютою
  через банк.

Перша розвідка сервера (`~/Downloads/discover.ps1`, 09.08) дивилась лише
список баз користувача `fedyshyn` (там одна: `kavetskiy`), реєстр кластера,
списки баз інших користувачів, бази SQL Server і живі сесії **ніхто не
дивився**. Тож питання «чи є на сервері база Бухгалтерії» досі відкрите.

## Скрипт 1: `probe-server-bases.ps1` — чи є інша база

Без облікових даних 1С. Читає:

| Розділ | Джерело | Що покаже |
|---|---|---|
| 0 | COM `ConnectAgent` → `GetInfoBases`, `GetSessions` | усі бази кластера і хто в них зараз сидить (бухгалтер!) |
| 1 | `1CV8Clst.lst` у `srvinfo` (шлях бере з командного рядка служби) | ім'я, опис, тип СУБД і назва бази SQL для кожної інфобази |
| 2 | `ibases.v8i` у профілях **усіх** користувачів | які бази відкриває кожен, хто заходить по RDP |
| 3 | `sqlcmd` (fedyshyn з 09.08 в адміністраторах — може пройти), інакше `.mdf` на диску | бази SQL з розміром і датою |
| 4 | пошук `1Cv8.1CD` | файлові бази (`D:\TestBase` — 0,51 ГБ, що це?) |
| 5 | процеси `1cv8*`, `rphost` з власником і командним рядком (паролі замасковано) | хто зараз працює і в якій базі |
| 6 | M.E.Doc: тека, підтеки обміну, найсвіжіші файли | звідки він бере податкові накладні |
| 7 | `D:\install`, шаблони конфігурацій, `*.cf/*.dt` | чи ставили «Бухгалтерію»/BAS (є `1C.Pred.8.3` від 10.03.2026) |
| 8 | усі встановлені програми | клієнт-банки, «Вчасно», інші облікові системи |

Запуск (32-бітний PowerShell, бо COM-конектор 32-бітний):

```
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -ep bypass -f \\tsclient\Downloads\probe-server-bases.ps1 > \\tsclient\Downloads\probe-server-bases.out.txt 2>&1
```

Якщо розділи 1–2 кажуть «cannot read»/«access denied» — повторити з
консолі «Запуск від імені адміністратора»: чужі профілі й `srvinfo` без
підвищення не читаються.

## Скрипт 2: `probe-accounting-in-ut.ps1` — бухгалтерський шар усередині УТ

Генерується з `gen-probe-accounting.py` (кирилиця в `.ps1` живе лише як
коди символів). 92 запити в 10 розділах, кожен у своєму try/catch:
неіснуючий об'єкт валить лише свій запит.

| Розділ | Що шукає | Навіщо сайту |
|---|---|---|
| A | організації (ФОПи/юрособи), каси, банківські рахунки, статті руху грошей, статті витрат, види договорів | розріз продажів і закупівель по юрособах; класифікатор видатків |
| B | РКО по видах операцій і статтях, ПП вихідне/вхідне, платіжні ордери, авансові звіти, регістр `ДенежныеСредства` з розбивкою «хто його рухає» (OTHER ≠ 0 = є невідомий документ грошей) | **реальні видатки** (пальне, зарплата з каси, оплати постачальникам) → справжня рентабельність, а не лише вал |
| C | взаєморозрахунки за знаком і видом договору, топ-15 кому винні ми, чим платимо постачальникам | **кредиторка** постачальникам (сайт зараз бачить лише дебіторку), валютні борги |
| D | регістр партій: собівартість залишку разом, по складах, по організаціях, **за роком оприбуткування**, топ-15 | склад у грошах закупівлі замість цін продажу; **неліквіди за віком** |
| E | інвентаризації, списання, оприбуткування, повернення постачальнику, переміщення, переоцінка | втрати й нестачі; повернення браку постачальнику |
| F | податкові накладні, вхідні податкові документи, ставки ПДВ у реалізаціях, рахунки на оплату | чи платник ПДВ ця база; чи можна виписувати рахунки з сайту |
| G | замовлення постачальнику, дод. витрати (доставка/мито), ГТД, прайси постачальників | розділ «Закупівлі» на реальних замовленнях; landed cost |
| H | чеки ККМ, звіти про роздрібні продажі | роздріб магазинів (тип цін «6.МАГАЗИНИ» натякає, що він є) |
| I | `РегистрБухгалтерии.Управленческий`, план рахунків, сальдо | готовий управлінський баланс, якщо його хтось веде |
| J | фізособи, зарплата, підрозділи | що з персоналу взагалі є в УТ (очікувано — нічого) |

Запуск (не в 20:00–20:30 — сервер 1С у цей час лежить):

```
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -ep bypass -f \\tsclient\Downloads\probe-accounting-in-ut.ps1 > \\tsclient\Downloads\probe-accounting-in-ut.out.txt 2>&1
```

Конфіг бере з `C:\Users\fedyshyn\budvik-agent\config.json` (користувач
`budvik_sync`). Очікуваний час — кілька хвилин: більшість запитів агрегатні
по регістрах за рік.

## Скрипт 3: `probe-expenses.ps1` — де живуть витрати і що ходить касою

З `gen-probe-expenses.py`. Розшифровує види операцій ПКО/РКО порівнянням із
`ЗНАЧЕНИЕ(Перечисление…)` (через `[string]` вони дали `<ref>`), розкладає
гроші по касах (шукаємо «БЕЗГОТІВКА ГРН»), читає коментарі 2535 РКО без
контрагента на 53,5 млн, і перебирає документи, де може стояти стаття
витрат: авансові звіти (ТЧ Прочее), послуги в надходженнях, заголовок РКО,
списання. Запуск — як скрипт 2, вивід `probe-expenses.out.txt`.

Виконано 05.09: каса УТ прохідна (РКО «прочие» 53,5 млн = здача виручки),
авансові звіти = зарплата за ролями, витрати пише `Документ.ПрочиеЗатраты`
у регістр `Затраты`.

## Скрипт 5: `probe-costs.ps1` — структура ПрочиеЗатраты і регістру Затраты

З `gen-probe-costs.py`, 44 запити: кандидати-реквізити шапки і ТЧ документа
(кожен окремо), виміри регістру, хто в нього пише, витрати за рік по групах
статей, статтях, місяцях і роках, ПКО по назві договору (куди закривається
«Безготівка»), `ПРЕДСТАВЛЕНИЕ()` для перелічень. Запуск — як скрипт 2,
вивід `probe-costs.out.txt`.

Виконано 05.09. Регістр `Затраты`: `Период, Регистратор, СтатьяЗатрат,
Подразделение, Сумма`, оборотний; пишуть `ПрочиеЗатраты` (ТЧ `Затраты`:
`СтатьяЗатрат, Сумма`) і `АвансовыйОтчет`. Витрат за рік 8,06 млн. Банківські
оплати клієнтів заносять ПКО в «каса грн» за договором «Безготівка» (16,2 млн
за рік). `ПРЕДСТАВЛЕНИЕ()` працює.

## Скрипт 4: `probe-buh-base.ps1` — що всередині Buhgalteria

З `gen-probe-buh.py`, 70 запитів під «Бухгалтерія для України 1.2»:
регістр Хозрасчетный і глибина історії, план рахунків, сальдо по всіх
рахунках, банк (ПП вхідні/вихідні, 31), каса, чи дублюються реалізації з УТ
через обмін, дебіторка 36 / кредиторка 63, податкові накладні й 64, зарплата
(66, нарахування), основні засоби (10/13), авансові звіти, доходи 70 /
собівартість 90 / витрати 9х за рік — скелет P&L.

Користувачі 1С живуть у кожній базі окремо, `budvik_sync` у Buhgalteria
немає. Потрібні облікові дані користувача **цієї** бази:

```
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -ep bypass -f \\tsclient\Downloads\probe-buh-base.ps1 -User "ІМ'Я" -Password "ПАРОЛЬ" > \\tsclient\Downloads\probe-buh-base.out.txt 2>&1
```

Без `-User` скрипт пробує зайти без імені — спрацює лише якщо в базі не
заведено жодного користувача.

**Користувача в 1С ми не заводимо** — це зміна в базі, а ми її тільки
читаємо. Потрібні дані наявного облікового запису Buhgalteria (того, під
яким туди заходить бухгалтер, або будь-якого іншого) — їх дає власник.
Якщо він захоче окремий обліковий запис лише для читання, заводить його
сам у 1С, а нам передає ім'я і пароль.

## Як читати вивід

- `OK label rows=N` — об'єкт є; `rows=0` — є, але порожній за період.
- `-- label: Object reference not set…` — об'єкта або одного з полів у цій
  конфігурації немає. Помилка не каже, чого саме, тому поруч завжди є
  запасний запит з іншими полями (A2/A3, B2/B3, I3/I4).
- У B5, B6, C9, C10 рядок `OTHER` з ненульовою сумою — гроші чи борг рухає
  документ, який ми не назвали. Це найцінніша знахідка: його треба знайти.
- Кодування виводу — UTF-16LE: на Mac `iconv -f UTF-16LE -t UTF-8 file`.

## Що робити з результатами

Порядок пріоритетів для нових каналів обміну, якщо об'єкти виявляться живими:

1. **Партії (D)** — найдешевше і найкорисніше: одна віртуальна таблиця дає
   оцінку складу в закупівельних цінах і вік залишку. Сьогодні склад на
   сайті оцінюється в цінах продажу з підписом про це.
2. **РКО зі статтями (B)** — видатки. Разом із валом з `ПродажиСебестоимость`
   це вже операційний прибуток по місяцях.
3. **Кредиторка (C)** — дзеркало дебіторки для розділу «Закупівлі».
4. **Банк** — лише якщо скрипт 1 знайде бухгалтерську базу. Тоді потрібен
   окремий користувач тільки на читання в тій базі і другий `config.json`.

Правило незмінне: 1С лише читаємо (`1c-read-only-rule`).
