# Підключення до 1С: покрокова інструкція

Документ для **власника проєкту**. Технічні деталі — у [1c-sync.md](1c-sync.md) та [agent/README.md](../agent/README.md).

## Головне, що треба зрозуміти одразу

**Логін до 1С, який вам дадуть, — це НЕ те, що потрібно для синхронізації.**

Звичайний обліковий запис 1С дозволяє людині працювати у програмі через вікно 1С. Але наша програма-агент не «сидить» у вікні 1С — вона звертається до бази по мережі. Для цього в 1С треба **окремо увімкнути веб-інтерфейс (OData)**, і зробити це може лише той, у кого є доступ до Конфігуратора — тобто ваш зовнішній фахівець з 1С.

Тому послідовність така:

1. Ви отримуєте доступ до системного блока (RDP) — щоб було куди встановити агента.
2. Фахівець з 1С вмикає OData і створює службовий обліковий запис **тільки для читання**.
3. Ми встановлюємо агента на той системний блок і запускаємо в тестовому режимі.

Крок 2 — критичний. Без нього решта не має сенсу.

---

## Крок 1. Що просити у того, хто дає доступ

Попросіть **доступ до самого системного блока**, а не лише до 1С:

- IP-адреса (або ім'я комп'ютера в мережі)
- логін і пароль **облікового запису Windows** з правами адміністратора
- дозвіл підключатися через віддалений робочий стіл (RDP)

Формулювання, яке можна переслати: «Потрібен адміністративний доступ по RDP до комп'ютера, де стоїть 1С, щоб встановити службу обміну даними з сайтом. Служба працює лише на читання — у 1С нічого не змінює.»

**Якщо RDP не дадуть** — це не глухий кут. Тоді агента встановлює ваш фахівець з 1С або системний адміністратор за нашою інструкцією ([agent/README.md](../agent/README.md)), а ми віддалено допомагаємо. Але свій доступ значно швидший.

## Крок 2. Технічне завдання для фахівця з 1С

Це найважливіша частина. Скопіюйте текст нижче і надішліть йому.

---

**Початок тексту для фахівця з 1С**

Доброго дня. Ми підключаємо інтернет-магазин до вашої бази 1С. Обмін працює **виключно на читання** — у 1С нічого не записується, не проводиться і не змінюється.

Прошу виконати три речі:

**1. Опублікувати базу на веб-сервері з увімкненим OData**

Конфігуратор → Адміністрування → Публікація на веб-сервері. Поставити галочку **«Публікувати стандартний інтерфейс OData»**.

Якщо на комп'ютері немає веб-сервера — потрібно встановити IIS (компонент Windows) або Apache. Публікація локальна, назовні відкривати нічого не треба.

**2. Задати склад стандартного інтерфейсу OData**

Потрібні для читання:
- довідники: Номенклатура, Контрагенти, Склади, Види цін
- регістр відомостей із цінами (зріз останніх)
- регістр накопичення із залишками на складах
- документи реалізації та надходження товарів
- регістр взаєморозрахунків з контрагентами

**3. Створити користувача 1С `budvik_sync` з правами ТІЛЬКИ на читання**

Окрема роль, у якій дозволено лише читання перелічених вище об'єктів. Без прав на запис, проведення, видалення, без доступу до Конфігуратора.

**Що прошу повідомити у відповідь:**

1. Адреса опублікованої бази, наприклад `http://localhost/budvik/odata/standard.odata`
2. Логін і пароль створеного користувача `budvik_sync`
3. Версія платформи (8.3.x) і назва конфігурації (УТ для України / BAS / УНФ / доопрацьована)
4. Режим бази: файловий чи клієнт-серверний
5. **Точні назви** (важливо — вони різні в різних конфігураціях):
   - регістру із залишками на складах
   - регістру взаєморозрахунків
   - видів цін для роздрібної та оптової ціни (потрібні їхні GUID — можна взяти з довідника Види цін)
6. Чи заповнений реквізит **Артикул** у номенклатури
7. Коли виконується резервне копіювання бази (щоб не призначити на цей час нічну звірку)

**Кінець тексту для фахівця з 1С**

## Крок 3. Що робите ви, поки чекаєте відповідь

Ці кроки не залежать від 1С і їх можна зробити паралельно.

**3.1. Створити секретний ключ**

Це спільний пароль між сайтом і агентом. Виконайте в терміналі:

```bash
openssl rand -hex 32
```

Отримаєте довгий рядок. Збережіть — знадобиться двічі.

**3.2. Додати змінні на Railway**

У проєкті Budvik → Variables:

| Змінна | Значення |
|---|---|
| `SYNC_AGENT_ID` | `budvik-1c-prod` |
| `SYNC_AGENT_SECRET` | рядок з кроку 3.1 |
| `SYNC_ALERT_CHAT_ID` | ваш Telegram-чат для сповіщень (за бажанням) |

**3.3. Застосувати міграцію бази**

```bash
npx prisma migrate deploy
```

Міграція лише додає нові поля — наявні дані не зачіпає.

---

## Крок 4. Перевірка доступу до 1С (коли фахівець відповів)

Підключіться по RDP до системного блока і відкрийте у браузері **на самому цьому комп'ютері**:

```
http://localhost/<ім'я бази>/odata/standard.odata/$metadata
```

Браузер попросить логін і пароль — введіть дані `budvik_sync`.

**Має з'явитися** велика XML-сторінка з переліком сутностей. Це означає, що все готово.

**Якщо помилка 404** — база не опублікована або неправильне ім'я в адресі.
**Якщо помилка 401** — невірний логін/пароль.
**Якщо сторінка порожня або мало сутностей** — не заданий склад інтерфейсу OData (пункт 2 у завданні фахівцю).

## Крок 5. Встановлення агента

На системному блоці з 1С:

1. Встановити **Node.js 20 LTS** — https://nodejs.org
2. Завантажити `nssm.exe` — https://nssm.cc/download — покласти в папку `agent\install\`
3. Скопіювати папку `agent` з проєкту на цей комп'ютер
4. У папці `agent` виконати:

```powershell
npm install
npm run build
Copy-Item config.example.json config.json
notepad config.json
```

У `config.json` заповнити:
- `ingestUrl` — адреса сайту на Railway
- `agentId` / `agentSecret` — те саме, що на Railway (крок 3.2)
- `odata.baseUrl`, `odata.username`, `odata.password` — дані від фахівця
- `entities.*` — точні назви з відповіді фахівця
- `priceTypes.retail` / `.wholesale` — GUID видів цін
- `preview` — залишити `true`

---

## Крок 6. Тестовий запуск

```powershell
node dist\agent.cjs --once --preview
```

**Режим preview нічого не змінює на сайті** — він лише читає 1С і показує, що́ саме змінилося б. Це безпечно запускати скільки завгодно разів.

Результат дивіться в адмінці сайту: **Адмін → ERP → Синхронізація**.

Що перевірити:
- товари знайшлися і зіставилися з наявними на сайті (а не всі позначені як «нові»)
- ціни й залишки виглядають правдоподібно
- категорії підтягнулися з груп 1С

**Якщо майже всі товари позначені як «нові»** — швидше за все не збігаються артикули. Це вирішується, але треба подивитись на дані.

---

## Крок 7. Бойовий запуск

Після тижня спостережень у preview:

1. У `config.json` поставити `"preview": false`
2. Встановити службу:

```powershell
# PowerShell від імені адміністратора
.\install\install-service.ps1
Start-Service BudvikSyncAgent
```

Далі агент працює сам: кожні 20 хвилин перевіряє зміни, щоночі робить повну звірку.

Найбільший ризик у графіку — крок 2: залежить від того, наскільки швидко відгукнеться зовнішній фахівець.

## Якщо OData увімкнути не вийде

Іноді на старих конфігураціях або через політику франчайзі OData недоступний. Тоді є запасний варіант: фахівець налаштовує регламентне вивантаження у файл (формат CommerceML), а агент читає папку з файлами.

Це на 2–3 дні більше роботи з нашого боку, але серверна частина лишається без змін. Повідомте, якщо дійде до цього — підготую окреме завдання для фахівця.
