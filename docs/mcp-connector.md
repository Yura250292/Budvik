# MCP-конектор: дані Budvik у Claude і ChatGPT

Керівник підключає дані фірми в **claude.ai** (Pro/Max) або **ChatGPT**
(Plus/Pro, режим розробника) як власний конектор і розмовляє з ними на своїй
підписці: «продажі по торгових за вересень стовпчиками», «залежність боргу від
днів без відвантаження», «ABC по брендах». Модель сама викликає наші
інструменти, отримує цифри з бази й будує діаграми (Claude — артефактом,
ChatGPT — Python).

Токени моделі оплачує підписка. Наш сервер лише віддає дані.

- Адреса конектора: **`https://mcp.budvik27.com/mcp`**
- Код: `src/lib/mcp/` (логіка, без `next/*`), `mcp/index.ts` (HTTP-сервіс),
  запуск і змінні — [mcp/README.md](../mcp/README.md)
- План упровадження: [docs/superpowers/plans/2026-09-23-mcp-connector.md](superpowers/plans/2026-09-23-mcp-connector.md)

## Як підключити

**Claude (claude.ai, веб, мобільний, Desktop):**
1. Налаштування → Конектори → «Додати власний конектор».
2. Назва — `Budvik`, адреса — `https://mcp.budvik27.com/mcp`. Client ID і
   Secret лишити порожніми.
3. Відкриється сторінка входу Budvik: email і пароль сайту. Пускає лише ADMIN.
4. У розмові увімкнути конектор (меню інструментів) і питати.

**ChatGPT (лише веб):**
1. Налаштування → Застосунки → Розширені налаштування → увімкнути «Режим розробника».
2. «Створити» застосунок: адреса `https://mcp.budvik27.com/mcp`, автентифікація OAuth.
3. Вхід — так само, email і пароль сайту.
4. У розмові обрати застосунок у режимі розробника.

Відключити будь-яке підключення — у профілі адміна на сайті, картка
«Підключені AI-застосунки» (`/admin/profile#ai-apps`). Там же адреса для копіювання.

## Що бачить модель

20 інструментів, усі лише на читання (`readOnlyHint`, ChatGPT не питає підтвердження):

| Інструмент | Що дає |
| --- | --- |
| `describe_data` | 41 представлення бази (продажі, рядки накладних, клієнти й борги, товари, склад, оплати, зміни, трек, маршрути, інтернет-замовлення, ціни 1С/сайту/ринку, пропозиції агента цін, ціни постачальників, наради, задачі, чат персоналу, потенційні клієнти, сезонність, сайт по днях…) і правила SQL |
| `query_db` | довільний `SELECT` над цими представленнями, до 500 рядків; відповідь — `columns` + `rows` масивами |
| 18 готових зведень | ті самі, що в помічника керівника: `team_overview`, `team_receivables`, `documents`, `stock_health`, `sales_analysis`, `money_flows`, `shifts_report`, `drivers_report`, `staff_profile`, `staff_now`, `drivers_today`, `site_report`, `sync_health`, `search_clients`, `client_profile`, `product_search`, `build_route` (план доставки на день з грошима рейсу й посиланнями Google Maps — нічого не пише), `meetings` (наради: рішення, теми, ризики, задачі команді, пошук у транскриптах) |

Зведення — явним списком у `src/lib/mcp/tools.ts`, а не «все, що бачить
керівник»: новий пишучий інструмент помічника назовні сам не потрапить.
Відносні посилання на екрани сайту («/admin/…») у відповідях зведень конектор
робить повними (`absolutizeLinks`): у claude.ai чи ChatGPT шлях нікуди не веде.

Логістика: «склади маршрути на завтра» — `build_route mode=day_plan`, поїздки
торгових — `shifts_report` (`mode=days` — по днях). Подробиці —
[assistant.md](assistant.md#логістика-гроші-рейсу-й-поїздки-торгових). Сервісу
потрібна змінна `OSRM_URL` (та сама, що на Vercel): без неї маршрути рахує
публічний демо-OSRM, який лімітує й падає.
`remind_me` (пише) і `export_file` (файли віддаються з кукою сайту) не віддаємо.

Інструкції сервера (`src/lib/mcp/instructions.ts`) коротко пояснюють моделі
словник: гроші в гривнях, київська доба, `real_sale`, повернення вже від'ємні,
спершу готові зведення, для графіків — агрегат у SQL.

## Безпека

Конектор видає дані всієї фірми назовні, тому захист тут шарами:

1. **Вхід лише ADMIN.** OAuth 2.1 з PKCE; роль перевіряється на **кожному**
   запиті, тож пониженого адміна живий токен не рятує.
2. **Реєстрація клієнтів відкрита (без неї claude.ai не підключиться), але
   редирект — лише на claude.ai, claude.com, chatgpt.com, chat.openai.com і
   localhost** (Claude Code). Чужий сайт не зареєструє «клієнта», щоб виманити код.
3. **Одне підключення = родина токенів.** Повтор коду, повтор refresh-токена
   чи refresh від чужого клієнта гасять родину цілком: вкрадене перестає
   працювати разом зі справжнім, людина просто входить знову. Refresh
   ротується на кожному оновленні. У базі — лише SHA-256 токенів.
4. **Довільний SQL — під окремою роллю Postgres `budvik_mcp_ro`**
   (`scripts/mcp/readonly-role.sql`). Поверх сканера й `READ ONLY` у
   `query-db.ts` сама база не дає ні писати, ні читати секрети: паролі,
   токени пристроїв, пушів, Google-календаря, MCP. Без
   `MCP_READONLY_DATABASE_URL` сервіс у проді не стартує.
5. **Журнал `McpCall`** — хто, яким застосунком, що саме (для `query_db` —
   сам SQL), скільки рядків, помилки. 90 днів. Стеля — 120 викликів/хв на
   людину; вхід — 5 спроб на 15 хв.

**1С конектор не чіпає взагалі:** він читає лише PostgreSQL сайту.

### Приватність

Відповіді інструментів (назви клієнтів, борги, суми) потрапляють у розмову,
тобто до Anthropic або OpenAI. На особистих тарифах у налаштуваннях обох
вимкнути використання розмов для навчання моделей (Claude: Privacy →
«Help improve Claude»; ChatGPT: Data controls → «Improve the model for everyone»).

## Розгортання

Окремий сервіс Railway **`budvik-mcp`** у проєкті «Budvik». Він не на Vercel:
челендж Vercel віддає 429 не-браузерним клієнтам, а OAuth-дискавері
Anthropic і OpenAI саме такі. І не у воркері: деплой конектора не має
перезапускати прийом обміну з 1С.

**Розгорнуто 23.09.2026.** Як це було зроблено (і як повторити):

1. Міграція `20260923160000_mcp_oauth` — `psql -1 -f …/migration.sql` по прод-базі, потім
   `prisma migrate resolve --applied 20260923160000_mcp_oauth` (історія міграцій проду
   розходилась із гілкою: там уже була `20260922190000_calendar_connector`).
2. Роль: `psql <адмінська адреса прод-бази> -v pwd=<пароль> -f scripts/mcp/readonly-role.sql`
   (пароль спершу згенерувати й зберегти — він іде в `MCP_READONLY_DATABASE_URL`), потім
   `MCP_READONLY_DATABASE_URL=… npx tsx scripts/check-mcp-readonly.mts` — на проді зелено.
3. Сервіс `budvik-mcp`, змінні з [mcp/README.md](../mcp/README.md)
   (`MCP_READONLY_DATABASE_URL` — через `${{Postgres.RAILWAY_PRIVATE_DOMAIN}}`),
   деплой — **лише `bash scripts/mcp/deploy.sh`**: Railway для нових сервісів ігнорує
   `railway.json` і збирав би весь сайт.
4. Домен `mcp.budvik27.com` — CNAME на `mjut9dfp.up.railway.app` у Cloudflare, **DNS only**.
5. `MCP_CHECK_EMAIL=… MCP_CHECK_PASSWORD=… npx tsx scripts/check-mcp-http.mts https://mcp.budvik27.com`.

**Після кожної міграції, що додає таблицю, яку читає вид `query_db`,** —
перезапустити `readonly-role.sql` (нові таблиці навмисно не відкриваються
ролі самі) і прогнати `check-mcp-readonly.mts`.

**Відкат:** зупинити сервіс `budvik-mcp` — конектор перестає працювати, сайт
і обмін з 1С не зачеплено.

## Перевірки

| Команда | Що доводить |
| --- | --- |
| `npm run check:mcp` | OAuth (атаки: чужий редирект, повтори, понижена роль), інструменти через MCP-клієнт, підключення в профілі. Лише локальна база |
| `scripts/check-mcp-http.mts <адреса>` | повний танець як у claude.ai: 401 → метадані → реєстрація → вхід → токени → MCP → оновлення |
| `scripts/check-mcp-readonly.mts` | роль `budvik_mcp_ro`: усі види читаються, секрети й запис — 42501 |

## Граблі, на які вже наступили

- **Кирилиця в `invalid_token`.** SDK кладе повідомлення в заголовок
  `WWW-Authenticate`, а Node на кирилиці там падає (`ERR_INVALID_CHAR`):
  замість 401, на який Claude/ChatGPT просять увійти знову, виходив 500, і
  конектор «вмирав» назавжди. Повідомлення `InvalidTokenError` — лише ASCII.
- **Секрет клієнта за замовчуванням протухає через 30 днів** (SDK). Для
  ChatGPT це тихий кінець доступу; вимкнено (`clientSecretExpirySeconds: 0`).
- **`authorization_response_iss_parameter_supported`** SDK 1.30 не оголошує,
  а ChatGPT на ньому будує стабільний callback — віддаємо свої метадані.
- У скриптах `.mts` під tsx SDK вантажиться двічі (ESM і CJS), тож
  `instanceof` класів помилок бреше — перевіряти за `errorCode`.
