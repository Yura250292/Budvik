# Конектор Google Calendar

Робочий день співробітника — задачі зі строком, а далі й маршрути доставки —
сам собою з'являється в окремому календарі «Budvik» у його Google-акаунті.

Налаштування в Google Cloud — `docs/calendar-setup.md` (робить власник руками).

## Як це влаштовано

```
StaffTask ─→ проєктор ─→ бажані події ─┐
                                        ├─→ дифф ─→ дії ─→ Google Calendar
CalendarEventLink (що вже відправлено) ─┘
```

**Прохід не слухає зміни в базі, а раз на дві хвилини звіряє результат.**
Задачі й маршрути пишуться з десятків місць (роути ERP, планувальник дня,
воркер нарад, скрипти) — хук у кожному з них можна забути, і забуте місце дасть
тихий розсинхрон на місяці. Звірення забути не можна: воно дивиться на те, що є.

Дифф порівнює відбиток змісту (`contentHash`) з тим, що лежить у мапінгу.
Збігся — жодного виклику до Google. Тому тік коштує один запит до Postgres.

## Що куди

| Файл | Про що |
|---|---|
| `src/lib/calendar/config.ts` | змінні, дозвіл, адреси; `calendarMissingEnv()` |
| `src/lib/calendar/crypto.ts` | шифрування постійного ключа доступу (AES-256-GCM) |
| `src/lib/calendar/state.ts` | підписаний `state` рукостискання |
| `src/lib/calendar/oauth.ts` | згода, обмін коду, оновлення, відкликання |
| `src/lib/calendar/api.ts` | клієнт Calendar v3 |
| `src/lib/calendar/connection.ts` | підключення, ключ доступу в пам'яті, календар «Budvik» |
| `src/lib/calendar/render.ts` | тіло події, сталий id, київські дати |
| `src/lib/calendar/diff.ts` | що вставити, виправити, прибрати |
| `src/lib/calendar/policy.ts` | вікно, стеля, беклоф |
| `src/lib/calendar/projectors/` | по файлу на сутність |
| `src/lib/calendar/sync.ts` | прохід воркера |
| `src/app/api/calendar/**` | connect / callback / status / disconnect |
| `src/components/cabinet/CalendarCard.tsx` | картка в профілі |

Таблиці: `CalendarConnection` (підключення людини) і `CalendarEventLink`
(мапінг «запис ↔ подія»). У бізнес-моделях **немає жодної колонки конектора**:
вимкнути його можна двома `DROP TABLE`.

## Три рішення, які варто знати

**Окремий календар і вузький дозвіл.** `calendar.app.created` дає доступ лише
до календарів, створених самим застосунком. Зіпсувати особисті події людини
технічно неможливо.

**Сталий id події.** `eventIdFor()` рахує id із сутності, ключа й людини. Тому
повторна вставка після обірваного запису впирається в 409 «вже є» замість
дубля — а під час `railway up` дві копії воркера живуть одночасно.

**Конектор не чіпає вхід.** `GoogleProvider` у `src/lib/auth.ts` лишається
входом покупця на вітрину. Календар має свій OAuth-клієнт і свої роути.

## Що потрапляє в календар

| Сутність | Умова | Вигляд |
|---|---|---|
| `StaffTask` | `ASSIGNED`, є `dueAt`, строк у вікні | подія на весь день |

Вікно — від учора до +14 днів (`policy.ts`). Учорашній день лишено, щоб
прострочена задача не зникала саме тоді, коли про неї треба пам'ятати.

Чернетки (`PROPOSED`) у календар не йдуть: виконавець їх ще не бачив.
Виконана або скасована задача зникає з календаря сама — подія існує рівно
доти, доки сутність є в бажаному стані.

## Стани підключення

- `ACTIVE` — працює.
- `NEEDS_RECONNECT` — Google відкликав дозвіл (людина забрала доступ у себе в
  акаунті). Це **стан, а не аварія**: у кабінеті жовта картка, одне
  повідомлення на добу, синхронізація цієї людини стоїть.
  Зміна пароля Google дозвіл не відкликає — це правило лише для Gmail.
- `DISABLED` — відключила сама. Календар у Google лишається: це її дані.

## Перевірка

```bash
npx tsx scripts/check-calendar-core.mts        # шифрування, id, дати, тіло події
npx tsx scripts/check-calendar-diff.mts        # що вставити/виправити/прибрати
npx tsx scripts/check-calendar-projector.mts   # які задачі видно, як читати Google
npx tsx scripts/check-calendar-oauth.mts       # state і адреса згоди

npx tsx --env-file=.env scripts/calendar-sync-dry.mts          # наміри, без запису
npx tsx --env-file=.env scripts/calendar-sync-dry.mts --live   # справжній прохід
```

Перші чотири не торкаються ні бази, ні мережі.

## Граблі

**Google не пускає OAuth у WebView** (`disallowed_useragent`). Тому
`mobile/src/app/cabinet.tsx` перехоплює `/api/calendar/google/connect` і
відкриває його системним браузером — саме початок потоку, а не сторінку
згоди: кука з nonce і сесія мусять бути в тому ж браузері, куди Google
поверне людину.

**Вторинний календар у телефоні буває вимкнений** за замовчуванням — про це
написано просто в картці профілю.

**Відповідь без постійного ключа доступу.** Якщо людина колись уже давала
дозвіл, Google може не віддати його вдруге. Підключення тоді не зберігається,
а кабінет каже забрати доступ на myaccount.google.com/permissions і
спробувати ще раз.
